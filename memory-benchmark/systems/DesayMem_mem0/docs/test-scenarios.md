# DesayMem 车机记忆系统 — 实地测试场景手册

> 在浏览器中打开 `scripts/cockpit_frontend.html`，按以下场景逐条执行。
> 服务地址：`http://47.115.228.135/memory`
> 每个场景标注了【操作】【预期结果】【验证要点】。

---

## 场景一：司机偏好记忆（单用户基础流程）

**用户**：司机 A（user_driver / 主驾）

### 步骤

| 轮次 | 司机说 | 预期车机回复 | 预期记忆存储 |
|------|--------|-------------|-------------|
| 1 | 我开车的时候喜欢把空调调到22度 | 好的，已为您设置空调温度到22度 | ✓ 语义：空调22度偏好 |
| 2 | 导航去上海迪士尼 | 正在为您规划前往上海迪士尼的路线 | ✓ 语义：导航目的地 |
| 3 | 开车时帮我放周杰伦的歌 | 已为您播放周杰伦的歌单 | ✓ 语义：周杰伦音乐偏好 |
| 4 | 帮我把座椅加热打开到3挡 | 座椅加热已调至3挡 | ✓ 过程性：座椅加热操作 |
| 5 | 我之前说的空调温度是多少度 | 根据您的记忆偏好，您喜欢把空调调到22度 | 无新记忆，仅召回 |

### 验证要点

1. 每轮对话后，右侧"记忆库"应实时新增对应记忆条目
2. 第 4 轮的记忆应显示 `过程性` 标签（黄色），其余为 `语义`（蓝色）
3. 第 5 轮是**跨轮召回**——不写入新记忆，验证系统从已有记忆中检索出"22度"
4. 对话区下方绿色提示框应显示"记忆已存储 (N 条)"

### 搜索验证

在输入框输入以下命令，验证召回：

```
搜索：空调温度
搜索：周杰伦
搜索：上海迪士尼
搜索：座椅
```

每条都应返回相关记忆，且 score 分数可见。

## 场景二：乘客隔离测试（多用户并发）

**前提**：先完成场景一，司机 A 已有记忆。

### 步骤 1 — 乘客登录

点击 **"熄火 / 切换用户"**，在登录页：

| 字段 | 选择 |
|------|------|
| 驾驶员 | 乘客 B（user_passenger） |
| 乘员位置 | 副驾 |

点击"点火启动"。

### 步骤 2 — 验证记忆库为空

**预期**：右侧记忆库显示"暂无记忆"，记忆总数为 0。

> 如果看到司机的记忆 → 隔离失败，需排查。

### 步骤 3 — 乘客写入不同偏好

| 轮次 | 乘客说 | 预期记忆 |
|------|--------|---------|
| 1 | 我喜欢把空调调到25度 | ✓ 空调25度偏好 |
| 2 | 导航去南京路步行街 | ✓ 导航目的地 |
| 3 | 帮我放林俊杰的歌 | ✓ 林俊杰音乐偏好 |

### 步骤 4 — 验证互不可见

在乘客对话中搜索：

```
搜索：空调温度
```

**预期**：只返回"25度"，**不应**出现"22度"。

### 步骤 5 — 隔离测试按钮

点击右侧面板 **"运行隔离测试"**。

**预期**：
- 当前用户记忆数：3
- 其他用户可查：隔离正常 ✓

### 步骤 6 — 切回司机验证

熄火 → 重新用司机 A 登录 → 搜索"空调温度"

**预期**：只返回"22度"，**不应**出现"25度"。乘客的导航和音乐记忆也不可见。

## 场景三：重复写入去重

**用户**：司机 C（user_driver2 / 主驾，全新用户）

### 步骤

| 轮次 | 司机说 | 预期 |
|------|--------|------|
| 1 | 我开车的时候喜欢把空调调到22度 | ✓ 存储记忆 |
| 2 | 我开车的时候喜欢把空调调到22度 | 无新记忆（去重） |
| 3 | 我开车的时候喜欢把空调调到22度 | 无新记忆（去重） |

### 验证要点

1. 第 1 轮：对话区显示"记忆已存储 (1 条)"
2. 第 2、3 轮：车机回复应正常，但**不显示**绿色"记忆已存储"提示
3. 右侧记忆库始终只有 **1 条**记忆，不会堆积
4. 记忆总数始终为 1

> 这验证了 MD5 content_hash 去重机制——相同内容不会重复入库。

## 场景四：偏好变更场景（当前架构的局限）

**用户**：司机 A（user_driver，已有场景一的 22 度记忆）

### 步骤

| 轮次 | 司机说 | 预期 |
|------|--------|------|
| 1 | 我现在觉得23度更舒服 | ✓ 新增"23度"记忆 |
| 2 | 搜索：空调温度 | 返回 22 度 **和** 23 度 |

### 验证要点

1. 第 1 轮成功存储新记忆（23度）
2. 第 2 轮搜索时，**两条**记忆同时出现

> **注意**：当前系统是 ADD-only，没有 UPDATE 路径。用户偏好变更时不会更新旧记忆，而是新增一条。新旧偏好同时存在于记忆库中。这是已知的架构局限，未来需要实现偏好冲突替代。

## 场景五：多轮上下文连续性

**用户**：全新用户，任意驾驶员身份

### 步骤

在一轮对话中连续说出多条偏好，验证系统的连续抽取能力：

| 轮次 | 司机说 | 预期记忆 |
|------|--------|---------|
| 1 | 我喜欢开高速的时候听摇滚乐 | ✓ 高速+摇滚乐 |
| 2 | 顺便帮我把窗户关一下 | ✓ 关窗操作 |
| 3 | 对了导航去苏州博物馆 | ✓ 导航目的地 |

然后搜索：

```
搜索：音乐
搜索：导航
搜索：窗户
```

### 验证要点

1. 每轮对话 LLM 应精准抽取不同的记忆事实
2. 搜索"音乐"应召回摇滚乐相关记忆
3. 搜索"导航"应召回苏州博物馆
4. 三条记忆的 `memory_type` 均为语义记忆

## 场景六：过程性记忆 vs 语义记忆

**用户**：任意驾驶员

### 步骤

| 轮次 | 司机说 | 预期记忆类型 |
|------|--------|-------------|
| 1 | 我习惯把后视镜调到最低位置 | 语义记忆 |
| 2 | 请按步骤教我怎么设置定速巡航 | 过程性记忆 |
| 3 | 我喜欢晚上开车时开近光灯 | 语义记忆 |

### 验证要点

1. 右侧记忆库切换到"过程性" Tab → 只看到第 2 条
2. 切换到"语义" Tab → 看到第 1、3 条
3. 第 2 条的记忆内容应是 LLM 生成的**步骤摘要**，不是原文

## 场景七：记忆删除与历史

**用户**：任意已有记忆的驾驶员

### 步骤

1. 在右侧记忆库中找到一条记忆，点击 **"删除"**
2. 删除后记忆库实时刷新，总数减 1
3. 搜索被删除记忆的关键词 → **不应**再召回

### 验证要点

1. 删除后记忆立即从列表消失
2. 搜索结果不包含已删除的记忆
3. 如果其他用户有相同内容的记忆 → 不受影响

## 场景八：多驾驶员切换（实际家庭场景）

模拟一个家庭共用一辆车的场景：

### 角色

| 驾驶员 | 用户 ID | 偏好 |
|--------|---------|------|
| 爸爸 | user_driver | 空调22度 / 周杰伦 / 导航去公司 |
| 妈妈 | user_passenger | 空调25度 / 林俊杰 / 导航去学校 |
| 爷爷 | user_driver2 | 空调28度 / 戏曲 / 导航去公园 |

### 步骤

1. **爸爸登录** → 说 3 句话 → 搜索"空调温度" → 确认只有22度 → 熄火
2. **妈妈登录** → 说 3 句话 → 搜索"空调温度" → 确认只有25度 → 熄火
3. **爷爷登录** → 说 3 句话 → 搜索"空调温度" → 确认只有28度 → 熄火
4. **爸爸重新登录** → 搜索"空调温度" → 确认**仍然只有22度**

### 验证要点

1. 三个用户互不干扰，各自只能看到自己的记忆
2. 爸爸第二次登录时，记忆完整恢复，不丢失
3. 三个用户搜索"空调温度"的结果分别为 22 / 25 / 28 度
4. 右侧"运行隔离测试"在任何用户下都应显示"隔离正常"

## 快速操作速查

| 操作 | 方式 |
|------|------|
| 发送对话 | 输入框打字 → 回车或点发送 |
| 搜索记忆 | 输入 `搜索：关键词` → 回车 |
| 快捷操作 | 点对话区下方按钮（空调/导航/音乐/座椅/召回/搜索） |
| 切换用户 | 左侧"熄火 / 切换用户" → 重新选择驾驶员 |
| 查看记忆 | 右侧记忆库，可按语义/过程性过滤 |
| 删除单条 | 右侧记忆卡片点"删除" |
| 隔离测试 | 右侧底部"运行隔离测试" |
| 刷新记忆 | 右侧顶部"刷新"按钮 |
