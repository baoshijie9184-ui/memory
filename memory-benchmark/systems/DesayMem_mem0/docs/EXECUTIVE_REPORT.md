## 一、我们在做什么

为德赛西威座舱助手建设**云端长期记忆系统**。用户在车里说的话，经过抽取、去重、分层存储后，下次需要时能准确召回——包括精确偏好、模糊指代和历史经历。

系统从 Mem0 OSS 2.0.18（ECAI 2025 论文，6 万+ GitHub star）迁移重构，使用独立 `desaymem` 命名空间，运行时不依赖 `mem0ai` 包，可自主演进。

---

## 二、解决了什么问题

| 用户场景 | 痛点 | DesayMem 的解决方式 |
|---------|------|-------------------|
| 上次说了空调 22 度，下次又问 | **记不住** | L3 画像独立表直读，每轮检索必带 |
| "上周那次""老规矩"命中不了 | **想不起** | L2 事件层 + 实体链接 + LLM 精排时间换算 |
| 旧偏好和新偏好混在一起返回 | **分不清** | ADD-only 真源 + 冲突消解只返回最新值 |

## 三、核心架构 — 三层记忆

```
对话输入
  → 写入七步（last-k → 近邻 → LLM 抽取 → 去重 → 入库 → 实体 → 派生 L2/L3）
  → 检索十阶段（归一化 → 向量+BM25 并集 → 组合打分 → 冲突消解 → LLM 精排）
  → 返回 { memories, profile }
```

| 层 | 是什么 | 存哪里 | 和 Mem0 的区别 |
|----|--------|-------|---------------|
| **L1 Fact** | 原子事实，只增不改 | PostgreSQL `memory_items` | Mem0 可被 UPDATE/DELETE 改写，我们 ADD-only 不可变 |
| **L2 Episode** | 一次经历的摘要，带绝对时间 | 同表，`memory_type=episodic_memory` | Mem0 无事件归组 |
| **L3 Profile** | 用户当前画像 | 独立表 `profile_beliefs`，主键直读 | Mem0 无独立画像层，偏好混在事实堆里 |

**关键设计原则：LLM 提建议、Python 管写库。** LLM 输出结构化 JSON 建议，Python 两道硬校验后执行写操作：证据 ID 必须真实存在；长期习惯需 ≥2 个不同自然日证据。任何上层错误都可从 L1 全量重建。

## 六、检索能力 — 十阶段混合

```
① 词形归一化 → ② 实体抽取 → ③ 查询向量化
→ ④ pgvector 语义 over-fetch → ⑤ BM25 关键词检索
→ ⑥ BM25 归一化 → ⑦ 实体加权 boost → ⑧ 候选并集
→ ⑨ 组合打分 + 冲突消解 → ⑩ LLM 语义精排
```

| 分量 | 最大权重 | 说明 |
|------|----------|------|
| 语义相似度 | 1.0 | cosine（pgvector HNSW） |
| BM25 | 1.0 | sigmoid 归一化（PostgreSQL tsvector） |
| 实体加权 | 0.5 | 同义实体合并 ≥0.95，查询命中关联记忆加分 |
| 时间衰减 | 0.15 | 30 天半衰期（`exp(-ln2*days/30)`） |

**冲突消解**：检测"改为""从现在开始"等 13 类显式更新表达 → 按 `(user, 属性)` 分组 → 时序排序 → 新值 SUPERSEDE 旧值，旧值不返回但保留审计。

**LLM 精排**：输入当前日期 + 查询 + 画像 + 候选（假编号防 LLM 编造 ID），完成相对时间换算（"上周"→ 日期区间）和意图判别（"一般开几度"看画像 vs "上次怎么回事"翻事件）。全程容错回退。

## 七、安全与隔离

- 所有检索/删除强制 `tenant_id + user_id` 双键隔离
- 非 root 容器运行（`desaymem` uid 1000）
- 日志脱敏 `api_key` / DSN / 数据库密码
- LLM Proxy：API Key 鉴权 + CORS 白名单 + 错误信息脱敏
- `delete_all` 需 `confirm=true`，彻底清除记忆 + 实体 + 画像 + 审计
- Schema 不自建：启动 `check_schema` 校验，不自动建表

### 8.2 基线评测结果（旧架构，三层上线前）

数据集：365 天车机对话，495 段会话，92 条记忆，5 条模糊查询 + 8 条画像查询。

| 用例 | 查询 | 结果 | 失败原因 |
|------|------|------|---------|
| fuzzy_01 | 经常去的亲子餐厅 | PASS | — |
| fuzzy_02 | 根据我爱吃的菜找个最近的地方 | **FAIL** | 偏好"少油/不要香菜"已写入但未召回 |
| fuzzy_03 | 空气不好按老规矩调整 | **FAIL** | "23 度"未写入（写入侧缺口） |
| fuzzy_04 | 西餐厅按习惯点餐 | PASS | — |
| fuzzy_05 | 上周亲子餐厅预定差不多的 | PASS | — |

汇总：must 通过 **3/5 (60%)**，macro must_recall=80%，Top1 命中率=40%。

两个 FAIL 恰好是新架构（L3 画像 + 冲突消解 + LLM 精排）针对性解决的场景。下一步是在新架构上完整回归对比。

### 8.3 待处理事项

| 优先级 | 事项 | 影响 |
|--------|------|------|
| **P0** | L2/L3 多步写入缺事务锁 | 并发写入数据不一致（单实例下暂无实际影响） |
| **P1** | 派生层失败无自动补偿 | L1 与 L2/L3 长期可能不一致 |
| **P1** | 每次检索附加 LLM 精排调用 | P95 延迟和成本需预算控制 |
| **P1** | SQLite 限制横向扩容 | 多副本部署受限 |

| **P2** | 冲突消解领域正则覆盖面有限 | 非中文/非车机表达漏判 |

## 九、和 Mem0 的核心差异

| 维度 | Mem0 OSS 2.0.18 | DesayMem | 解决的痛点 |
|------|-----------------|----------|-----------|
| 记忆结构 | 单层扁平事实库 | L1/L2/L3 三层，派生层可重建 | 记不住 |
| 稳定偏好 | 与海量事实竞争向量排序 | 独立表主键直读，每轮必带 | 记不住 |
| 更新机制 | LLM 直接 UPDATE/DELETE | LLM 建议 + Python 校验，ADD-only 可审计 | 分不清 |
| 新旧共存 | 无处理 | 检索截断前冲突消解，只返回最新值 | 分不清 |
| 时间理解 | 无相对时间机制 | L2 绝对时间 + LLM 精排时间换算 | 想不起 |
| 指代消解 | 无（新版有实体链接） | 实体链接 boost + BM25 并集 + 画像反馈 | 想不起 |
| 检索范式 | 向量主导 | 双路并集 + 组合打分 + 语义精排 | 想不起 |
| 场景适配 | 通用英语助手 | 中文车机词典、多租户隔离、Proxy 安全加固 | — |
| 验证方式 | 引用公开基准 | 自建 365 天 / 13 用例车载年度评测 | — |
