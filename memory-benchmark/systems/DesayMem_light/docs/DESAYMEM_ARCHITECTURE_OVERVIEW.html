完整包与Checkpoint

一个Profile处理包必须包含Cross-Event、全部summarizes当前Event及少量related_to历史Sk。Token不足时后续完整包留到下一批，Profile Checkpoint只推进到最后成功处理的Cross-Event。

技术来源与我们的改造

LightMem

参考Session近期上下文、Topic切分与轻量异步沉淀。

改造：完整Turn、10分钟空闲、可配置容量、TTL Embedding缓存和云端持久化Job。

Mem0

参考七步写入、九步检索及新旧Fact操作。

改造：在Topic后一次抽取，保留Message证据、时间、Tag及Event绑定。

StructMem

参考Cbuf、历史Sk与Cross-Event总结。

改造：显式Event、中心向量召回、完整Cbuf摘要、covered/seed/support区分和数据库Checkpoint。

Memos

参考Tag与时间轴组织。

改造：Tag/时间贯穿Fact、Event、Cross与QueryPlan，并与向量检索组合。

TiMEM + LangMem + AWS

参考层级Persona、Profile/Collection、Schema与Preference Consolidation。

改造：开放Profile + 固定Preference双轨，增加条件、多值、作用域、证据和显式/隐式门槛。

Semantic Router + RouteLLM

参考Embedding语义路由与低成本/强模型级联。

改造：复用BGE-M3查询向量，复杂、时间与多路请求升级Qwen。

VehicleMemBench

参考多用户偏好冲突与车辆工具执行评测。

定位：作为后续车载基线，不直接照搬KV或Summary记忆实现。

云端工程模式

PostgreSQL SKIP LOCKED、租约、幂等、CAS、Transactional Outbox与资源舱壁。

原因：让算法在多租户、多Worker和模型故障下仍可追溯恢复。
