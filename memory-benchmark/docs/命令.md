# Mem0 + LoCoMo 常用命令

本文中每个 Bash 代码块都能独立、整段粘贴执行，不依赖预先定义的 Shell 变量。服务器项目路径为 `/data/pengshuang/memory-benchmark`。

## 1. 参数说明

| 参数 | 含义 |
| --- | --- |
| `--sample-limit 1` | 测试前1个样本；`0` 表示全部10个样本 |
| `--build-limit 10` | 每个样本构建前10个 chunk；`0` 表示全部 |
| `--full` | 取消每样本前20题的冒烟限制，测试全部约1986题 |
| `--top-k 5` | 每道题最多检索5条记忆 |
| `--ingest-workers 2` | 最多同时调度2个样本进行异步 ingest |
| `--write-concurrency 1` | Mem0/Qdrant 实际同时写入数；本地 Qdrant 建议保持1 |
| `--qa-workers 4` | 最多同时发出4个异步 QA 请求 |
| `--output-dir PATH` | 报告目录，不是 Qdrant 记忆目录 |

当前异步适配器按照官方 `CHUNK_SIZE=1`，即1个有效 turn 等于1个 chunk，也等于1次 `Mem0.add()`。第一个 LoCoMo 样本共有19个 session、419个有效 turn。

> 同步修正版和异步版分别使用固定的本地 Qdrant 目录。不要同时运行两个同步任务，也不要同时运行两个异步任务。

## 2. screen 命令

### 2.1 创建并进入会话

```bash
screen -U -S locomo_async_full
```

进入后运行第4.2节的异步全量命令。让任务继续运行并退出界面：先按 `Ctrl+A`，松开，再按 `D`。

### 2.2 查看、进入和关闭

```bash
screen -ls
```

下面的数字改成 `screen -ls` 显示的真实 ID：

```bash
screen -U -r 1616410.locomo_async_full
```

会话显示 `Attached` 时，强制断开旧终端并进入：

```bash
screen -U -d -r 1616410.locomo_async_full
```

查看会话进程树和最近输出：

```bash
pstree -ap 1616410
screen -S 1616410.locomo_async_full -X hardcopy -h /tmp/locomo_async_full.log
tail -n 50 /tmp/locomo_async_full.log
```

关闭多余会话，执行前确认它不是需要保留的任务：

```bash
screen -S 1616460.locomo_async_full -X quit
```

检查是否还有评测进程：

```bash
pgrep -af 'run_fixed.py|run_async_fixed_prompt.py|run_full_fixed.sh' || echo 'No evaluation process'
```

### 4.3 分步版的目录和规则

分步入口是 `datasets/VehicleMem-Eval/run_async_phased.py`。它把建库和 QA 拆成两个独立进程：

1. `--phase ingest` 只调用 Mem0 写入记忆，不检索、不生成答案。
2. `--phase evaluate` 只打开已有记忆库，进行检索、答案生成和 Token-F1 计算。
3. 两个阶段必须使用相同的 `--run-id`、`--sample-limit` 和 `--model-config`。
4. 首次建库使用一次 `--fresh`；中断后续跑时绝对不要再带 `--fresh`。

示例 `run-id` 为 `locomo-smoke-20260918`，对应的独立记忆目录是：

```text
/data/pengshuang/memory-benchmark/datasets/VehicleMem-Eval/results/mem_data/mem0_async_phased_memory-llm_locomo-smoke-20260918
```

不同 `run-id` 使用不同 Qdrant 和 history 数据库，因此不会删除或覆盖同步版、旧异步版以及其他分步任务的记忆。直接使用本地 Qdrant 时建议保持 `--write-concurrency 1`；这里的分步设计主要解决长任务中断和重复建库，不承诺让 Mem0 抽取变快。

### 4.4 首次只建冒烟库

下面只为前2个样本各写入前10个 chunk，不执行 QA。`--chunk-size 1` 与官方 LoCoMo 的 `CHUNK_SIZE=1` 一致，即一个有效 turn 调用一次 `Mem0.add()`：

```bash
cd /data/pengshuang/memory-benchmark/datasets/VehicleMem-Eval && MEM0_TELEMETRY=False PYTHONPATH=. ../../envs/mem0/bin/python -B -u run_async_phased.py --phase ingest --run-id locomo-smoke-20260918 --dataset locomo --memory-system mem0 --model-config memory-llm --sample-limit 2 --build-limit 10 --chunk-size 1 --ingest-workers 1 --write-concurrency 1 --log-every 1 --fresh
```

这条命令成功结束后会打印 `Ingest complete`。记忆已经保存在独立 Qdrant 目录中，即使尚未执行 QA 也不会被清空。

### 4.5 中断后继续建同一个库

如果上一步被 `Ctrl+C`、断网或进程退出打断，执行下面这条命令。它读取 `ingest_checkpoint.json`，从每个样本的下一个未完成 chunk 继续；这里故意没有 `--fresh`：

```bash
cd /data/pengshuang/memory-benchmark/datasets/VehicleMem-Eval && MEM0_TELEMETRY=False PYTHONPATH=. ../../envs/mem0/bin/python -B -u run_async_phased.py --phase ingest --run-id locomo-smoke-20260918 --dataset locomo --memory-system mem0 --model-config memory-llm --sample-limit 2 --build-limit 10 --chunk-size 1 --ingest-workers 1 --write-concurrency 1 --log-every 1
```

续跑时 `--run-id`、`--sample-limit`、`--build-limit`、`--chunk-size` 和 `--model-config` 必须与首次建库完全相同，否则程序会拒绝运行，防止混写。

### 4.6 对已经建好的冒烟库做 F1 评测

下面不会重新 ingest，也不会调用 Judge LLM。它只检索同一个 `run-id` 的记忆、用七步提示词生成答案并计算本地 Token-F1：

```bash
cd /data/pengshuang/memory-benchmark/datasets/VehicleMem-Eval && MEM0_TELEMETRY=False PYTHONPATH=. ../../envs/mem0/bin/python -B -u run_async_phased.py --phase evaluate --run-id locomo-smoke-20260918 --dataset locomo --memory-system mem0 --model-config memory-llm --sample-limit 2 --top-k 5 --qa-workers 2 --answer-max-tokens 2000 --output-dir /data/pengshuang/memory-benchmark/results/raw/20260918_locomo_mem0_phased_smoke
```

QA 同样有检查点。中断后原命令再次执行会跳过已经完成的问题，并把前后两次请求的 token 和耗时合并到最终报告。只有想丢弃旧 QA 结果并从第1题重测时，才在命令末尾增加 `--fresh-evaluation`；它不会删除记忆库。

### 4.7 全量分步建库

## 9. 查询同步 Qdrant 记忆

## 13. 常见提醒

1. `--sample-limit` 控制样本数，`--build-limit` 控制构建多少 chunk，`--full` 控制是否解除每样本前20题限制。
2. 异步版七步提示词只用于答案生成；Mem0 记忆抽取使用 Mem0 内部提示词。
3. `ADD` 数量不等于 `Mem0.add()` 调用次数。一次 add 可能生成0条、1条或多条记忆。
4. `history.id`、`memory_id` 和 `user_id` 不同。两个样本应有两个 `user_id`，但通常有很多 `memory_id`。
5. 本地 Qdrant payload index 警告不影响本地过滤，只表示不能使用服务端索引优化。
6. spaCy 的 Click 弃用警告不影响模型加载和评测运行。
7. 当前异步报告只统计 QA 客户端 Token；Mem0 内部构建和检索尚未接入相同统计器。
8. 异步报告的 QA Runtime 是请求耗时之和；实际总耗时看 shell `time` 的 `real`。
