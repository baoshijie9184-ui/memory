# 日常运维与故障排查

## 1. screen 使用

登录后先恢复 PATH：

```bash
export PATH=/data/pengshuang/desaymem/envs/screen/bin:$PATH
```

永久配置：

```bash
echo 'export PATH=/data/pengshuang/desaymem/envs/screen/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
```

```bash
screen -ls                       # 查看
screen -r llm                    # 进入
screen -d -r memory-backend      # 强制接管已连接会话
```

退出到后台：`Ctrl+A`，再按 `D`。停止进程：进入会话后 `Ctrl+C`。

## 2. 推荐启动顺序

1. PostgreSQL
2. Qwen3-32B
3. BGE-M3
4. DesayMem 后端
5. Windows 本地 LLM Proxy 和前端

推荐停止顺序与此相反。

## 4. 常见故障

### `screen: command not found`

```bash
export PATH=/data/pengshuang/desaymem/envs/screen/bin:$PATH
```

### `curl: command not found` 或 `ss: command not found`

这是精简容器，不代表服务异常。使用 Python `urllib`、`ps -ef | grep '[u]vicorn'` 或读取 `/proc/net/tcp`。

### 记忆写入 502，LLM 400

查看错误是否为上下文超限。当前应为 Qwen 16K、后端输出 2000。验证 `/v1/models` 的 `max_model_len`。

### 中文被写成日语

确认 `src/desaymem/extraction/prompts.py` 的 `ADDITIVE_EXTRACTION_PROMPT` 中存在 Language Preservation，并重启后端。旧的日语记录不会自动修复。

### Profile distillation failed

L1 通常仍已保存。检查后端前后相邻日志、LLM 返回 JSON、`profile_beliefs`/`user_profile_snapshots` 表和迁移状态。

### 下载卡住

白名单网络可能对大文件 CDN 超时。优先使用 ModelScope 断点续传，保留已有目录后重试，不要先删除已下载分片。

### OOM

```bash
nvidia-smi
```

先确认 GPU4 上是否有其他进程；将 LLM `gpu-memory-utilization` 从 0.84 降为 0.82，或降低 `max-num-seqs`。Embedding 约 2.2GB 权重，但运行峰值仍需预留。

### ECC

GPU4 曾出现 1 个 Volatile Uncorrectable ECC 计数。若持续增加或出现 Xid/CUDA 错误，应保存 `nvidia-smi -q` 输出并联系管理员检查硬件。

## 5. 日志和进程

```bash
ps -ef | grep -E '[v]llm|[u]vicorn|[p]ostgres'
nvidia-smi
tail -n 200 /data/pengshuang/desaymem/logs/postgres.log
```

建议后续把三个 screen 服务改为受控启动脚本或 systemd/supervisor，并为日志增加轮转。
