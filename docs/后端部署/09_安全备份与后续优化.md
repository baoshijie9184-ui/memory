# 安全、备份与后续优化

## 1. 当前风险

记忆后端监听 `0.0.0.0:20142` 且尚无独立 API 鉴权。能访问该端口的客户端可能构造任意 `tenant_id/user_id`，从而读取、写入或删除记忆。LLM 的 20140 Key 不能保护 20142。

正式共享前应增加：

- Bearer API Key 或统一身份认证；
- Key 到 tenant/user 权限映射，不能完全信任请求体 ID；
- 删除接口的更高权限；
- CORS 白名单，替代 `allow_origins=["*"]`；
- 访问日志、审计日志和限流；
- Key 轮换，禁止提交 `.env`。

## 2. 备份策略

建议：

- 每日 PostgreSQL `pg_dump`；
- 每日 SQLite 一致性备份；
- 保留最近 7 天日备份和最近 4 周周备份；
- 定期在另一目录验证恢复，而非只确认备份文件存在；
- 模型无需高频备份，但应记录模型来源、版本和校验信息。

备份至少包括：

```text
PostgreSQL dump
history.db
.env（加密保管）
Git 提交 SHA
模型版本与启动参数
```

## 3. 监控指标

- API：请求数、P50/P95 延迟、4xx/5xx、写入成功率。
- LLM：input/output tokens、排队时间、生成速度、上下文超限、OOM。
- Embedding：batch 大小、编码延迟、错误率。
- 数据库：连接数、库大小、慢查询、备份结果。
- 质量：提取成功率、重复率、中文保持率、时序冲突正确率、召回率、画像更新成功率。

## 4. 推荐后续开发优先级

1. 给 20142 增加认证和 tenant/user 授权。
2. 修复并建立 Profile distillation 自动测试。
3. 将全局 2000 输出拆成按任务 token 预算。
4. 对超长对话做分块/摘要，减少巨大固定提示词。
5. 增加结构化输出 schema 与失败重试，减少 JSON 解析问题。
6. 完善时序冲突测试：旧偏好、明确更新、撤销、临时偏好。
7. 增加端到端回归数据集和一键 smoke test。
8. 建立版本发布记录：代码 SHA、迁移版本、模型版本、配置摘要。
9. 将 screen 逐步替换为可自动拉起和健康恢复的进程管理方案。
